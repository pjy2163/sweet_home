# Data Dictionary

## region_master

모든 데이터의 기준 지역 테이블입니다.
법정동 연계정보 원천은 과거 개정 이력을 포함하므로, `region_master`는 `시도명 + 시군구명 + 행정동명` 기준 최신 `개정일자`의 행정동코드만 사용합니다.

| 컬럼명 | 설명 |
| --- | --- |
| region_id | 서비스 내부 지역 ID. 초기에는 `행정동코드`와 동일 |
| 시도명 | 시/도 이름 |
| 시군구명 | 시/군/구 이름 |
| 행정동코드 | 행정동 코드 |
| 행정동명 | 행정동 이름 |

## dong_mapping

법정동과 행정동을 연결하는 매핑 테이블입니다.
법정동 연계정보 원천의 과거 이력 때문에 같은 행정동명에 과거/현재 행정동코드가 함께 존재할 수 있으므로, MVP 매핑은 최신 `개정일자` 기준으로 생성합니다.

| 컬럼명 | 설명 |
| --- | --- |
| 행정동코드 | 행정동 코드 |
| 행정동명 | 행정동 이름 |
| 법정동코드 | 법정동 코드 |
| 법정동명 | 법정동 이름 |
| 시도명 | 시/도 이름 |
| 시군구명 | 시/군/구 이름 |
| 개정일자 | 코드 개정일자 |
| 연결번호 | 법정동 연계정보의 연결번호 |

### real_estate_fact

서울 전월세 실거래 데이터를 행정동/월 단위로 집계한 테이블입니다.

원천 데이터는 법정동 기준이므로 `dong_mapping`을 사용해 행정동 기준으로 변환합니다.
하나의 법정동이 여러 행정동에 연결되는 경우, 초기 MVP에서는 연결된 행정동 수만큼 거래량을 균등 배분합니다.

| 컬럼명 | 설명 |
| --- | --- |
| region_id | 행정동 기준 지역 ID |
| 기준일자 | 계약월. `YYYY-MM` 형식 |
| 실거래가 | 전월세 전체 거래의 평균 보증금. 단위: 만원 |
| 전세가 | 전세 거래의 평균 보증금. 단위: 만원 |
| 전세가율 | 매매가 대비 전세가 비율. 매매가 데이터 연결 전까지 비워둠 |
| 거래량 | 행정동 매핑 가중치를 적용한 거래 건수 |

### real_estate_price_comparison

`real_estate_fact`를 기반으로 서울 평균 대비 지역별 가격 수준을 계산한 비교용 데이터 마트입니다.
첫 번째 MVP 화면과 리포트는 이 테이블을 우선 사용합니다.

서울 평균은 같은 `기준일자` 안에서 `거래량`을 가중치로 사용해 계산합니다.
`거래량_해석주의`가 `True`인 행은 거래량이 3건 미만이므로 가격 수준을 단정적으로 표현하지 않습니다.

| 행정동명 | 행정동 이름 |
| 기준일자 | 계약월. `YYYY-MM` 형식 |
| 실거래가 | 전월세 전체 거래의 평균 보증금. 단위: 만원 |
| 서울평균_실거래가 | 같은 월 서울 전체 평균 보증금. 단위: 만원 |
| 실거래가_서울평균대비율 | 지역 평균 보증금이 서울 평균 대비 높은/낮은 비율. 단위: % |
| 실거래가_서울평균대비금액 | 지역 평균 보증금과 서울 평균의 차이. 단위: 만원 |

| 서울평균_전세가 | 같은 월 서울 전체 평균 전세 보증금. 단위: 만원 |
| 전세가_서울평균대비율 | 지역 평균 전세 보증금이 서울 평균 대비 높은/낮은 비율. 단위: % |
| 전세가_서울평균대비금액 | 지역 평균 전세 보증금과 서울 평균의 차이. 단위: 만원 |
| 거래량 | 행정동 매핑 가중치를 적용한 거래 건수 |
| 거래량_해석주의 | 거래량이 3건 미만이면 `True` |

### population_fact

서울 생활인구 데이터를 행정동/월 단위로 집계한 테이블입니다.

초기 MVP에서는 서울 열린데이터광장의 `행정동 단위 서울 생활인구(내국인)` 원천을 사용합니다.
이 원천은 특정 시점에 특정 행정동에 존재하는 인구를 제공하므로, 월별 평균 `생활인구`를 먼저 채웁니다.
`주민등록인구`와 `세대수`는 주민등록 기반 원천을 추가 확보한 뒤 보강합니다.

| 컬럼명 | 설명 |
| --- | --- |
| region_id | 행정동 기준 지역 ID |
| 기준일자 | 집계 기준월. `YYYY-MM` 형식 |
| 주민등록인구 | 주민등록 기준 인구. 별도 원천 확보 전까지 비워둠 |
| 생활인구 | 월별 평균 생활인구 |
| 세대수 | 세대 수. 별도 원천 확보 전까지 비워둠 |

## 예정 Fact Tables

### safety_fact

서울 안전 대체 지표를 행정동 단위로 집계한 테이블입니다.

초기 MVP에서는 범죄율을 직접 제공하지 않습니다. 행정동 단위 공식 범죄 데이터 확보가 어렵고,
범죄율은 주거지 추천 맥락에서 낙인과 해석 리스크가 크기 때문입니다.
대신 주소 또는 좌표 기반으로 행정동 매핑이 가능한 안심시설과 유흥시설 지표를 우선 사용합니다.
구현 테이블명은 범죄 발생률 중심 의미를 피하기 위해 `safety_fact`를 사용합니다.

| 컬럼명 | 설명 |
| --- | --- |
| region_id | 행정동 기준 지역 ID |
| 기준일자 | 집계 기준일 또는 기준월. 원천 갱신 단위에 따라 `YYYY-MM-DD` 또는 `YYYY-MM` 형식 |
| 안심시설수 | 안심택배함, 안심귀갓길 안전시설물, 지킴이집 등 안전시설 수 |
| 유흥시설수 | 영업 중인 유흥주점/단란주점 수 |
| CCTV수 | CCTV 수. 자치구 단위만 확보될 경우 MVP에서는 비워두거나 별도 보조 지표로 분리 |
| 경찰시설수 | 경찰서, 지구대, 파출소 등 치안시설 수. 공식 위치 원천 확보 전까지 비워둠 |
| 매핑방법 | `행정동코드`, `주소지오코딩`, `좌표공간조인`, `자치구보조` 중 하나. 여러 전처리 산출물이 결합되면 사용된 방법을 쉼표로 나열 |
| 데이터출처 | 집계에 사용한 원천 데이터셋 이름. 전처리 산출물의 `데이터출처` 값을 보존 |

현재 MVP의 `유흥시설수`는 서울시 유흥주점영업/단란주점영업 인허가 원천에서 `상세영업상태명 = 영업`이고 좌표가 유효한 row를 SGIS 행정동 경계에 공간조인해 집계합니다.
SGIS `ADM_CD`는 SweetHome `region_id`와 코드체계가 달라 SGIS 코드집의 행정동명과 `region_master`의 `시군구명 + 행정동명`을 기준으로 변환합니다.
`region_master`는 최신 행정동코드 기준으로 중복 행정동명을 제거하므로, SGIS 서울 행정동 426개를 모두 매핑할 수 있습니다.
2026-06-25 기준 안심시설 raw 또는 행정동 매핑 중간 CSV는 아직 확보되지 않아 `안심시설수`는 0으로 유지합니다.
안심시설 원천이 추가되면 `safe_facilities_YYYYMMDD.csv`, `safety_facilities_YYYYMMDD.csv`, `safe_parcel_locker_YYYYMMDD.csv`, `safe_return_home_YYYYMMDD.csv` 중 하나의 패턴으로 저장하고, 시설 1개를 1 row로 유지한 뒤 `build_safety_fact.py`에서 집계합니다.
