# MVP Report Spec

이 문서는 SweetHome MVP 지역 비교 리포트의 입력, 출력, 해석 기준을 정의합니다.

MVP 리포트는 후보 행정동 2개의 가격, 생활인구, 안전 대체 지표, 상권 지표를 같은 `region_id` 기준으로 비교합니다.

## Goal

사용자가 후보 지역 2개를 입력하면 다음 질문에 답합니다.

> 두 후보 지역은 가격, 생활인구, 생활환경, 상권 규모 참고 지표에서 어떤 차이가 있는가?

리포트는 매물 추천, 투자 판단, 특정 지역 우열 판단을 하지 않습니다. 제공하는 정보는 사용자가 후보 지역을 비교하기 위한 참고 지표입니다.

후보지를 모르는 사용자가 지도 기반 탐색에서 한 지역을 선택하는 경우에도, 상세 화면은 같은 리포트 원칙을 따릅니다. 탐색 점수는 사용자가 조절한 가중치 기준의 상대적 적합도이며, 리포트는 해당 지역의 지표가 서울 평균 또는 비교 대상 대비 어떤 수준인지 설명합니다.

## Data Source

리포트는 다음 snapshot mart를 사용합니다.

```text
data/processed/region_comparison_snapshot.csv
```

이 mart는 가격, 생활인구, 안전 대체 지표, 상권 지표를 행정동 기준으로 결합합니다.

```text
real_estate_price_comparison
population_fact
safety_fact
commercial_fact
→ region_comparison_snapshot
→ report
```

도메인별 최신 기준일 또는 기준월이 다를 수 있으므로, 리포트는 각 지표의 기준 시점을 함께 표시합니다. 가격 지표는 법정동-행정동 매핑 영향으로 인접 행정동이 같은 값을 가질 수 있습니다.

## Input

CLI 입력은 다음 형태입니다.

```bash
.venv/bin/python src/report/generate_report.py --a 개포1동 --b 개포4동
```

구 이름까지 지정해야 하는 경우 다음처럼 입력합니다.

```bash
.venv/bin/python src/report/generate_report.py --a "강남구 개포1동" --b "강남구 개포4동"
```

| 인자 | 필수 여부 | 설명 |
| --- | --- | --- |
| `--a` | 필수 | 첫 번째 후보 행정동 |
| `--b` | 필수 | 두 번째 후보 행정동 |
| `--month` | 미지원 | 과거 가격 리포트 호환용 인자. snapshot 리포트에서는 사용할 수 없음 |

## Region Resolution

사용자는 행정동명으로 입력하지만, 내부 조회는 `region_id` 기준으로 수행합니다.

처리 규칙:

- `개포1동`처럼 행정동명만 입력하면 행정동명으로 조회합니다.
- `강남구 개포1동`처럼 구와 행정동명을 함께 입력하면 둘 다 일치하는 지역을 조회합니다.
- 같은 행정동명이 여러 구에 있으면 구 이름을 함께 입력하도록 오류를 반환합니다.
- 존재하지 않는 지역이면 오류를 반환합니다.

## Output Sections

리포트는 다음 섹션으로 구성합니다.

1. 리포트 제목
2. 리포트 목적 문장
3. 서울 평균 가격 지표
4. 후보 지역 A 지표
5. 후보 지역 B 지표
6. 해석 문장
7. 데이터 기준과 한계

## Metrics

| 지표 | 설명 |
| --- | --- |
| 가격 기준월 | 가격 지표가 산출된 계약월 |
| 평균 보증금 | 전월세 전체 거래의 평균 보증금 |
| 서울 평균 보증금 | 같은 기준월 서울 전체 평균 보증금 |
| 서울 평균 보증금 대비 | 지역 평균 보증금이 서울 평균보다 높은/낮은 비율 |
| 평균 전세가 | 전세 거래의 평균 보증금 |
| 서울 평균 전세가 | 같은 기준월 서울 전체 평균 전세 보증금 |
| 서울 평균 전세가 대비 | 지역 평균 전세가가 서울 평균보다 높은/낮은 비율 |
| 거래량 | 행정동 매핑 가중치를 적용한 거래 건수 |
| 거래량 해석 주의 | 거래량이 낮아 평균 가격의 대표성이 약할 수 있음을 표시 |
| 생활인구 | 행정동 기준 생활인구 |
| 안심시설수 | 행정동 기준 안심시설 개수 |
| 유흥시설수 | 행정동 기준 유흥주점/단란주점 영업 시설 개수 |
| 업종수 | 행정동 기준 서비스 업종 코드 종류 수 |
| 사업체수 | 행정동 기준 점포 수 합계 |

## Interpretation Rules

가격 수준 문구는 서울 평균 대비율을 기준으로 생성합니다.

| 조건 | 문구 |
| --- | --- |
| `+10%` 이상 | 서울 평균보다 높은 편입니다 |
| `-10%` 이하 | 서울 평균보다 낮은 편입니다 |
| `-10%` 초과, `+10%` 미만 | 서울 평균과 비슷한 범위입니다 |
| 데이터 없음 | 서울 평균과 비교하기 어렵습니다 |

후보 지역 간 전세가 차이는 다음 기준을 사용합니다.

| 조건 | 문구 |
| --- | --- |
| 차이 `5%p` 이상 | 더 높은 지역과 차이를 표시 |
| 차이 `5%p` 미만 | 큰 차이가 아니라고 표시 |

거래량이 낮은 지역이 하나라도 있으면 가격 수준을 단정적으로 해석하지 않는다는 문장을 추가합니다.

생활인구 데이터가 없는 지역이 하나라도 있으면 인구 지표 비교에 제한이 있다는 문장을 추가합니다.

안전 대체 지표는 범죄율이 아니므로 안전하거나 위험하다는 결론으로 표현하지 않습니다.

상권 지표는 점포와 업종의 규모 참고 지표이며 매출, 수익성, 투자성을 뜻하지 않습니다.

## Boundaries

리포트는 다음 표현을 사용하지 않습니다.

- 이 지역을 선택하세요
- 이 지역이 더 좋습니다
- 추천 지역입니다
- 가장 살기 좋은 지역입니다
- 이 지역은 안전합니다
- 이 지역은 위험합니다
- 투자 가치가 높습니다
- 가격이 오를 것입니다
- 장사가 잘 됩니다
- 수익성이 높습니다

리포트는 다음 표현을 사용합니다.

- 서울 평균보다 높은 편입니다
- 서울 평균과 비슷한 범위입니다
- 선택한 조건 기준 가중 점수가 상대적으로 높습니다
- 거래량이 적어 해석에 주의가 필요합니다
- 안전 대체 지표는 생활환경 참고 지표입니다
- 상권 지표는 점포/업종 규모 참고 지표입니다
- 후보 지역 비교를 위한 참고 정보입니다

## Future Exploration Report

지도 기반 후보지 탐색이 추가되면 리포트는 다음 흐름으로 확장합니다.

1. 사용자가 안전, 편의, 교통, 가격, 인구 가중치를 조절합니다.
2. 시스템은 행정동별 기본 도메인 점수에 사용자 가중치를 적용합니다.
3. 화면은 "추천"이 아니라 "선택한 조건 기준 상위 후보"를 표시합니다.
4. 사용자가 특정 행정동을 선택하면 상세 리포트에서 평균 대비 지표와 데이터 기준을 설명합니다.

가중 점수는 사용자의 현재 조건을 반영한 계산 결과이며, 스위트홈이 정한 절대 순위가 아닙니다.

```text
- 한계: 도메인별 기준일자가 다를 수 있으며, 안전 지표는 범죄율이 아니라 안전 대체 지표입니다. 가격 지표는 법정동-행정동 매핑 영향으로 인접 행정동이 같은 값을 가질 수 있습니다. 상권 지표는 매출이나 투자성을 뜻하지 않습니다.
```

## Future Extensions

다음 단계에서는 리포트 출력 로직을 API와 웹 화면에서 재사용할 수 있도록 비교 결과 모델을 분리할 수 있습니다.

확장 지표도 같은 원칙을 따릅니다.

- 행정동 기준으로 정규화합니다.
- 기준일 또는 기준월을 명시합니다.
- 데이터 출처와 한계를 표시합니다.
- 추천이 아니라 비교 근거로 표현합니다.
